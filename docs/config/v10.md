# Deskmate application config v10

Status: **frozen, readable through migration to [v11](v11.md)**. The store reads
v10 and v11. This document preserves the v10 input shape; it does not accept brightness. The web companion historically exchanged this shape
with the Rust server through the
`/v1/app/*` API; it does not read or write the file directly.

The complete UTF-8 file is limited to 65,536 bytes. Objects are closed: unknown fields
are rejected at the root and in every nested struct or tagged variant. Unless an
accepted-input default is called out below, every displayed field is required.

## Complete root shape

```json
{
  "schema_version": 10,
  "preferences": {
    "timezone": "UTC",
    "autostart": false,
    "paused": false,
    "orientation": "landscape"
  },
  "cards": [
    {
      "kind": "clock",
      "id": "clock",
      "title": "Desk",
      "show_seconds": true,
      "template": { "kind": "digital-clock" },
      "tap_action": { "kind": "none" },
      "refresh": { "kind": "device-local" },
      "alert": { "kind": "none" },
      "dwell_seconds": null
    }
  ],
  "image_sources": [],
  "assets": [],
  "advance": { "kind": "manual" },
  "updater": { "channel": "stable", "checks": "notify" }
}
```

`schema_version` must be the integer `10`. `cards` is ordered and that order is the
display loop; there is no second grouping or ordering structure. Card, image-source,
and asset IDs are separate namespaces, so the same string may occur once in each.

Two accepted-input defaults are load-bearing:

- `image_sources` may be omitted and then means `[]`;
- `preferences.orientation` may be omitted and then means `landscape`.

Serialization normalizes both fields back into the document. A card's
`dwell_seconds` may likewise be omitted or explicitly `null`; both mean no per-card
override and serialize as `null`. These are v10 input rules, not migrations.

## Preferences

`preferences` is a closed object with:

| Field | Type | Rule |
| --- | --- | --- |
| `timezone` | string | Required, nonblank IANA timezone, at most 64 UTF-8 bytes. |
| `autostart` | boolean | Host preference retained in the document. |
| `paused` | boolean | Whether the host runtime is paused. |
| `orientation` | string | `landscape` (90°) or `landscape-flipped` (270°); omission defaults to `landscape`. |

Portrait orientations and an on-device rotation setting do not exist.

## Cards and the loop

A document contains 1..=8 cards. Each card is a closed tagged object with a unique,
nonblank `id` of at most 32 UTF-8 bytes. `title` and `label` strings are at most 64
UTF-8 bytes and may be empty. Every card is in the loop; each successfully lowered
card becomes one protocol-v2 `CardConfig`, and no card-library-outside-the-loop state
exists.

### Clock

```json
{
  "kind": "clock",
  "id": "clock",
  "title": "Desk",
  "show_seconds": true,
  "template": { "kind": "digital-clock" },
  "tap_action": { "kind": "none" },
  "refresh": { "kind": "device-local" },
  "alert": { "kind": "none" },
  "dwell_seconds": null
}
```

A clock's template is exactly `digital-clock` or `analog-clock`. Its refresh policy is
exactly `device-local`. The host builds its scene, while the device advances the clock
between pushes.

### Pomodoro

```json
{
  "kind": "pomodoro",
  "id": "focus",
  "label": "Focus",
  "duration_seconds": 1500,
  "template": { "kind": "progress-ring" },
  "tap_action": { "kind": "start-pause" },
  "refresh": { "kind": "device-local" },
  "alert": {
    "kind": "on-timer-finish",
    "hold": { "kind": "until-dismissed" }
  },
  "dwell_seconds": null
}
```

`duration_seconds` is `1..=86400`. The only valid template is `progress-ring`; refresh
is `device-local`. `start-pause` and `reset` tap actions are valid only on a pomodoro
using that template.

### Picture

```json
{
  "kind": "picture",
  "id": "usage",
  "title": "Claude limits",
  "source_id": "claude-limits",
  "tap_action": { "kind": "none" },
  "refresh": { "kind": "manual" },
  "alert": { "kind": "none" },
  "dwell_seconds": null
}
```

`source_id` is a nonblank identifier of at most 32 UTF-8 bytes and must resolve to an
entry in `image_sources`. A picture has no `template`: the pushed raster frame is the
complete face. Its refresh policy is `manual` or `interval`; interval remains an
accepted authoring value even though a producer push determines when the picture
actually changes. An interval is `1..=1440` minutes.

Any external producer credential is deliberately absent. The server stores only its
digest in a separate source store and returns the plaintext token once when the source
is minted; server-owned faces need no producer credential.

### Shared card behavior

`template` is a closed tagged object. Its complete v10 variant set is:

- `digital-clock`;
- `analog-clock`;
- `progress-ring`.

`tap_action` is a closed tagged object with these shapes:

- `none`;
- `start-pause`;
- `reset`;
- `dismiss`;
- `open-url { url }`;
- `open-application { application_id }`.

An `open-url` target is nonblank HTTP(S), includes a host, contains no userinfo or
password, and is at most 2,048 bytes. An application ID is nonblank, at most 2,048
bytes, and contains no slash, backslash, or control character. Protocol v2 can lower
only `none`, `start-pause`, and `reset`; a save using a host-only action currently
fails compilation with `requires-capability` rather than silently changing its tap
meaning.

A picture card's `tap_action` describes what the *device* does by itself, which is
nothing, and it stays `none`. The host lowers every picture card to the wire's
`StartPause` regardless, because that is the only way protocol v2 reports a tap at all;
what the tap then means is the host's decision, and for a server-rendered face it is a
re-render. See `docs/superpowers/specs/2026-09-23-deskmate-tap-to-face-design.md`. No
stored file, validation rule or wire byte changes because of this paragraph.

`refresh` is `device-local`, `manual`, or `interval { minutes }`. The interval bound is
`1..=1440`; the card-kind compatibility rules above still apply.

`alert` is `none` or `on-timer-finish { hold }`. The latter is valid only on a
pomodoro. `hold` is `until-dismissed` or `seconds { value }`, with `value` in
`5..=600`. Alert hold is host-side bookkeeping and never clears the physical panel;
the panel's interrupt remains until its device-side dismissal path runs.

Each card accepts `dwell_seconds` as a missing field, `null`, or an integer in
`5..=3600`. Missing and `null` mean “use the document's timed default.” Manual advance
retains the value but does not use it.

## Image sources

`image_sources` contains at most 8 closed objects:

```json
{
  "id": "claude-limits",
  "name": "Claude limits"
}
```

Source IDs are unique, nonblank, and at most 32 UTF-8 bytes. Names are nonblank and at
most 48 UTF-8 bytes. Multiple picture cards may name one source. A missing reference
is the typed `missing-reference` validation failure, never a valid blank face.

The whole `image_sources` field may be omitted on v10 input and defaults to `[]`.

## Assets

At most 16 assets may be declared. Asset IDs are unique, nonblank, and at most 32
UTF-8 bytes. Every asset contains:

```json
{
  "id": "inter",
  "source": { "kind": "file", "value": "/fonts/Inter-Regular.ttf" },
  "kind": { "kind": "font" },
  "maximum_bytes": 262144
}
```

The only source variant is `file`; its nonblank value is at most 2,048 bytes.
`maximum_bytes` is `1..=262144`, and the sum across the document is at most 1,048,576
bytes. The closed asset-kind variants are:

- `font`, a TTF/OTF whose size is chosen per text node;
- `image`, an image converted to LVGL's binary representation by the host;
- `icon-font { glyphs }`, a TTF/OTF plus 1..=256 mappings of
  `{ "name": string, "codepoint": integer }`.

An icon name is unique within its asset, nonblank, and at most 64 UTF-8 bytes. A
codepoint must be a Unicode scalar value: no surrogate and no value above `0x10FFFF`.
A nonempty asset list requires the device's asset-transfer capability.

## Advance and updater

`advance` is a closed tagged object:

- `manual`; or
- `timed { default_dwell_seconds }`, whose value is `5..=3600`.

Timed advance is host-owned. The device has no independent loop timer in this config
contract.

`updater` is a closed object. `channel` is `stable`, `beta`, or `manual`; `checks` is
`disabled` or `notify`.

## Validation and strict decoding

Every tagged object rejects fields outside its selected variant, including unit
variants such as `{ "kind": "manual" }`. The implementation uses explicit field-set
validation for internally tagged enums because serde's derive attribute alone does not
enforce that rule on every such variant.

The current validation-code vocabulary is:

`unsupported-version`, `empty`, `too-long`, `too-many`, `duplicate-id`,
`missing-reference`, `out-of-range`, `invalid-timezone`, `invalid-source`,
`invalid-composition`, `too-large`, and `requires-capability`.

Validation is separate from decoding: valid JSON in the v10 shape can still produce a
typed `ValidationFailed` outcome with structured issues. It is never installed as
last-good.

## Persistence, refusal, and recovery

The store reads a small `schema_version: u32` header before deserializing the body.
Version 10 is decoded strictly as the shape above, then migrated in memory to v11
with `preferences.brightness: 78` (raw panel level 200, matching the existing final
boot level). The origin is `migrated`; loading never rewrites the file. An explicit
save writes v11. Version 11 follows [its own contract](v11.md). Every other integer
version is refused as `StoreError::UnsupportedVersion { found, supported: 11 }`;
the rest of an old- or future-shaped body is not interpreted. A missing, negative,
noninteger, or
overflowing version header is invalid JSON rather than an unsupported integer version.

A refused, malformed, invalid-UTF-8, oversized, unreadable, or validation-failed file
is left byte-for-byte untouched. A genuine last-good config remains the fallback when
one exists; otherwise built-in defaults provide safe in-memory continuity. Defaults
used for recovery are never recorded as genuine last-good. A missing file is different:
it is a clean defaults load and no file is created.

The browser reports an ordinary load refusal as
`recoverable-error { message }`. Domain validation uses
`validation-failed { message, issues }`, with the exact message “Your saved settings
failed validation and were not applied.” Because the saved path still exists,
`has_saved_config` remains true and the page does not present recovery as first run.
The complete persistence-state vocabulary remains `clean`, `saving`,
`recoverable-error { message }`, and `validation-failed { message, issues }`.

A linked panel whose saved file is refused still starts on the same safe fallback. The
per-device refusal remains visible in browser event/snapshot and admin snapshot output,
including across link reconnects, until an explicit successful save clears it. One
device's refusal does not block server startup, device listing, or another device's
load/link/runtime.

Successful saves validate and compile first, replace the file atomically with mode
`0600`, update genuine last-good only after replacement succeeds, and then apply the
configuration to a linked runtime. Validation, compilation, and atomic-persistence
failures preserve both the prior bytes and the prior last-good state. Reconciliation
or runtime-application errors reported after a successful replacement do not roll
back the persisted settings or last-good state.

## Wire and deployment boundaries

Schema v10 compiles to protocol v2 without changing any wire byte. `ApplyConfig`
carries card identity, tap meaning, and rotation; timers use `PushTimer`; faces use the
single host-built scene path. Dwell, advance, alerts, updater settings, and source
credentials are host-side concerns.

`app_core::CURRENT_SCHEMA_VERSION` in
`companion/crates/app-core/src/config.rs` is the single source constant and is now
`11` in the v11 build. The store migrates this v10 shape before compilation.
Deploy the v11 server before the matching SPA. Brightness is gated by capability bit
11, so existing v2 firmware keeps receiving ApplyConfig without that key; no
flash-first ordering is required.
