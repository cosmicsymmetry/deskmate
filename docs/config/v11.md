# Deskmate application config v11

Status: current, additive data-card contract. The companion owns this JSON document;
the webview exchanges the same shape through typed IPC but does not read or write the
file directly. The complete UTF-8 document is limited to 65,536 bytes and unknown fields
are rejected at every level.

This document supersedes `docs/config/v10.md`. **v11 adds `weather`, `rss` and `token`
as first-class card kinds.** The ordered `cards` array remains the one loop, dwell remains
a card field, and `advance` remains the document-level pacing setting. The protocol,
firmware and capability word do not change.

## Root and stable identity

```json
{
  "schema_version": 11,
  "preferences": {},
  "cards": [],
  "image_sources": [],
  "assets": [],
  "advance": { "kind": "manual" },
  "updater": {}
}
```

All v10 root fields and bounds are unchanged. `cards` is ordered and that order is the
loop; `MAX_CARDS` remains 8. Card ids remain stable identity and are limited to 32 UTF-8
bytes. Every card carries `id`, `tap_action`, `refresh`, `alert` and nullable
`dwell_seconds`; every kind except Pomodoro also carries the owner's `title`.

## Card kinds

Clock, Pomodoro and Picture keep their v10 shapes and meanings. Clock and Pomodoro are
device-live faces. Picture is the externally produced raster face and still names an
entry in the document-level `image_sources` array:

```json
{
  "kind": "picture",
  "id": "usage",
  "title": "Claude limits",
  "source_id": "claude-limits",
  "tap_action": { "kind": "none" },
  "refresh": { "kind": "manual" },
  "alert": { "kind": "none" },
  "dwell_seconds": null
}
```

Weather, RSS and Token are server-rendered raster faces. Their configuration is part of
the card itself, rather than an image-source declaration or a server-side spec file.
The server derives an internal source id from stable card identity as `card-{id}`. That
id is neither stored in the document nor offered as a setting: changing a source selector
would change what the card *is*, not tune the card the owner added.

### Weather

```json
{
  "kind": "weather",
  "id": "outside",
  "title": "Outside",
  "location": "Dubai",
  "units": "metric",
  "tap_action": { "kind": "none" },
  "refresh": { "kind": "interval", "minutes": 15 },
  "alert": { "kind": "none" },
  "dwell_seconds": null
}
```

`location` is required and limited to 256 UTF-8 bytes. `units` is `metric` or
`imperial`; omission defaults to `metric` when an older or hand-authored document is
read.

### RSS

```json
{
  "kind": "rss",
  "id": "headlines",
  "title": "News",
  "feed_url": "https://news.ycombinator.com/rss",
  "feed_title": "Hacker News",
  "tap_action": { "kind": "none" },
  "refresh": { "kind": "interval", "minutes": 15 },
  "alert": { "kind": "none" },
  "dwell_seconds": null
}
```

`feed_url` is required, bounded by the existing URL limit and must be an absolute
`http` or `https` URL. `feed_title` is the owner's short eyebrow inside the rendered
face; `title` remains the quiet card name used by the companion.

### Token

```json
{
  "kind": "token",
  "id": "market",
  "title": "SOL",
  "coin_id": "solana",
  "currency": "usd",
  "api_key": null,
  "tap_action": { "kind": "none" },
  "refresh": { "kind": "interval", "minutes": 15 },
  "alert": { "kind": "none" },
  "dwell_seconds": null
}
```

`coin_id` is required and limited to 128 UTF-8 bytes. `currency` is required, limited
to 16 bytes and defaults to `usd` when omitted. `api_key` is optional and limited to
512 bytes; it is supplied only to the existing CoinGecko provider and never enters the
device protocol.

## Refresh and delivery

The three data kinds require `RefreshPolicy::Interval { minutes }`, using the existing
1..=1440 minute bound. There is no second cadence field. The server converts minutes to
seconds and applies its existing 60-second to six-hour clamp before starting one
refresher per card.

Delivery is the Picture path after the producer step: the server renders SVG to a
canonical RGB565 frame, stores it as a durable asset, and pushes a single full-canvas
image scene. A derived source is created by the server without a bearer token before its
first frame is accepted. Only Picture cards participate in `image_sources` reference
validation; derived sources are not author declarations.

All outbound weather, feed and market requests continue through the server's bounded
`EgressHttpClient` and SSRF guard. v11 adds no route and no second HTTP client.

## Migration and compatibility

Migration from v10 is additive: the v10 document is parsed into the v11 shape unchanged
and reported as `MigratedV10`. No field transformation is performed. The first explicit
save writes `schema_version: 11` through the ordinary atomic store path.

Older readable documents still follow their existing migrations before entering the
v11 model. Unknown future schema versions, malformed, truncated, oversized or invalid
documents remain typed recoverable errors. Source bytes are not rewritten until an
explicit save.

## Deployment boundaries

`app_core::CURRENT_SCHEMA_VERSION` in `companion/crates/app-core/src/config.rs` is the
single source constant, now **11**. The server binary and installed companion app each
compile their own copy, so deployment remains ordered:

1. Redeploy the server binary.
2. Rebuild and reinstall Deskmate.app.
3. Only then save a document at schema v11.

Saving before both readers understand v11 produces the typed unsupported-version error;
it is not a firmware or protocol compatibility problem.
