# Deskmate application config v8

Status: current, subtractive card-authoring contract. The companion owns this JSON
document; the webview exchanges the same shape through typed IPC but does not read or
write the file directly. The complete UTF-8 document is limited to 65,536 bytes and
unknown top-level, card, image-source, playlist, playlist-entry, template, action, or
structured variant fields are rejected at every level.

This document supersedes `docs/config/v7.md`. **v8 is the first subtractive schema
bump:** it removes the device-rendered `calendar`, `weather`, `json-feed`, and `rss` card
kinds, together with the calendar-only `before-event` alert. A v7-or-older document can
therefore lose cards and playlist entries when it is loaded. The surviving card kinds
are `clock`, `pomodoro`, `plugin`, and `picture`.

The protocol-v1 wire contract and firmware are unchanged. `TemplateKind` and every
scene builder retain their complete renderer vocabulary; v8 narrows only which scenes
can be reached by authoring a card. `PROTOCOL_CURRENT_CAPABILITIES` is unchanged.

## Why the contract became smaller

Clock and Pomodoro need device-local updates between host pushes. Calendar, weather,
JSON-feed, and RSS cards do not: their data changes at server cadence, and curated
plugins can render those faces more flexibly on the server without another built-in
card contract. Keeping both paths would leave two implementations of the same product
surface, so v8 removes the device-rendered authoring path instead of deprecating it.

## Root and stable identity

```json
{
  "schema_version": 8,
  "preferences": {},
  "cards": [],
  "image_sources": [],
  "assets": [],
  "playlists": [],
  "active_playlist_id": "my-playlist",
  "updater": {}
}
```

Preferences, image sources, assets, playlists, templates, tap actions, refresh policies,
and updater settings keep their v7 shapes and bounds. Card, image-source, asset, and
playlist IDs remain separate namespaces.

## Card kinds

The two device-local kinds are unchanged:

- `clock` compiles to its authored digital- or analog-clock template;
- `pomodoro` compiles to `progress-ring` and retains its timer actions and
  `on-timer-finish` alert.

The two server-rendered kinds are also unchanged in shape:

```json
{
  "kind": "plugin",
  "id": "aqi",
  "title": "Air quality",
  "plugin_id": "aqi",
  "tap_action": { "kind": "none" },
  "refresh": { "kind": "interval", "minutes": 15 },
  "alert": { "kind": "none" }
}
```

```json
{
  "kind": "picture",
  "id": "usage",
  "title": "Claude limits",
  "source_id": "claude-limits",
  "tap_action": { "kind": "none" },
  "refresh": { "kind": "manual" },
  "alert": { "kind": "none" }
}
```

A plugin card's `plugin_id` is its identity, selected when the card is added. The editor
shows that identity and the catalog's installation state but does not offer to exchange
it for another plugin. Its refresh control remains: interval policy is what schedules
provider work, while manual policy intentionally schedules none.

A picture card continues to name a document-level image source. Its source selector and
all v7 image-source validation rules remain unchanged. Plugin and picture cards still
populate the frozen wire template field with `TemplateKind::DigitalClock`; the value
does not choose their renderer.

## Alerts

The closed alert variants are now:

- `none`, valid on every card;
- `on-timer-finish`, valid only on Pomodoro and carrying the unchanged hold policy.

`before-event` is not accepted. It existed only for the removed calendar card, so v8
removes both its document shape and its host-side evaluation deadline. Pomodoro alert
holds and interrupt takeover behavior are unchanged.

## Migration and compatibility

Every v0-v7 load removes cards whose kind is `calendar`, `weather`, `json-feed`, or
`rss`, then removes every playlist entry naming one of those cards. An inactive playlist
left empty is removed.

The active playlist is never allowed to disappear or remain empty. If all of its entries
were retired, migration adds the same digital clock card `AppConfig::default()` builds
and one entry naming it. The playlist itself is repaired in place, not replaced: its id,
name, and pacing survive, and the card is reused rather than duplicated when one with
that identity is already in the library. This deliberate data loss is what lets deployed
v7 documents containing only retired cards remain loadable and leaves the panel showing a
valid face. Surviving cards, entries, image sources, assets, preferences, and updater
settings are otherwise preserved.

Unknown future schema versions, malformed, truncated, oversized, or invalid documents
remain recoverable typed errors. Source bytes are not rewritten until an explicit save.
The transaction order remains: merge command-owned preferences, validate and compile,
check connected-device capabilities, atomically persist, replace runtime state, then
queue full replay.

## Deployment boundaries

`app_core::CURRENT_SCHEMA_VERSION` in
`companion/crates/app-core/src/config.rs` is the single source constant, now `8`. The
server binary and installed companion app each compile their own copy, so a schema bump
has three ordered boundaries:

1. Redeploy the **server** binary.
2. Rebuild and reinstall **Deskmate.app**.
3. Only then save a document at schema v8.

Saving before both readers understand v8 produces the typed unsupported-version error;
it is not a firmware or protocol compatibility problem.
