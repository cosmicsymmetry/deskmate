# Deskmate wire protocol v1

Status: the M1 registry (IDs 1-8 and error codes 1-9) is frozen; M2 extends the same
wire version with IDs 9-12 and error codes 10-14. M3 adds only optional fields, and M4
freezes an additive capability handshake before introducing more features. V2 Task 1
adds IDs 13-14 (`NetworkConfig`, `FactoryReset`), error code 15 (`WrongTier`),
capability bit 7 (`Networking`), and `StatusResponse` keys 24-30 — this defines the wire
shape and its decode/encode/validation only; device-side handling (NVS provisioning,
tier switching, `Ack` acceptance for the new types) lands in later V2 tasks. The asset
store's wire messages add IDs 15-18 (`AssetBegin`, `AssetChunk`, `AssetCommit`,
`AssetRelease`), gated on capability bit 5 (`AssetTransfer`), `Ack` key 2
(`already_present`), and `StatusResponse` key 31 (asset store capacity). The scene
renderer adds ID 19 (`PushScene`), gated on capability bit 8 (`SceneRender`);
bit 9 (`VolatileAssets`) additively gates the volatile form of `AssetBegin`,
including its optional RGB565 RLE encoding;
`CURRENT_CAPABILITIES` is now `1003`. Multi-byte
envelope integers are little-endian. CBOR integers use RFC 8949 deterministic
shortest-form encoding; every array and map is definite-length and every map's keys are
in deterministic order.

## Framing

Each packet is `COBS(decoded) || 00`. Empty delimiters are ignored. The decoded bytes
are:

| Offset | Size | Field |
|---:|---:|---|
| 0 | 1 | wire version (`1`) |
| 1 | 1 | message type |
| 2 | 2 | flags (`0` in v1) |
| 4 | 4 | request ID; responses echo it |
| 8 | 2 | payload length |
| 10 | N | canonical CBOR payload |
| 10+N | 4 | CRC-32C of all preceding decoded bytes |

The maximum decoded frame is 2048 bytes, therefore payloads are at most 2034 bytes and
COBS frames including their delimiter are at most 2058 bytes. A receiver that exceeds
the encoded limit discards through the next zero delimiter, reports one overflow, and
then resumes. Bad COBS, length, CRC, flags, payload, and unsupported-version/type errors
must not poison the following frame. CRC-32C uses the reflected Castagnoli polynomial
`0x82f63b78`, initial/final XOR `0xffffffff`; `"123456789"` hashes to `0xe3069283`.

Host requests use nonzero IDs. A response has the same ID and exactly one of the
documented response types. IDs may wrap, skipping zero. `DeviceEvent` is the sole
unsolicited type and always uses request ID zero; request ID zero on any other type, or
a nonzero ID on `DeviceEvent`, is invalid. The host allows one outstanding request per
connection and times it out after 2000 ms. A long-lived M2 session demultiplexes
request-ID-zero events while that request is in flight.

## Registry

| ID | Name | Direction | Response |
|---:|---|---|---|
| 1 | `StatusRequest` | host to device | `StatusResponse` |
| 2 | `StatusResponse` | device to host | — |
| 3 | `TimeSync` | host to device | `Ack` |
| 4 | `Ack` | device to host | — |
| 5 | `PushData` | host to device | `Ack` |
| 6 | `Heartbeat` | host to device | `HeartbeatAck` |
| 7 | `HeartbeatAck` | device to host | — |
| 8 | `Error` | device to host | — |
| 9 | `ApplyConfig` | host to device | `Ack` |
| 10 | `ActivateScreen` | host to device | `Ack` |
| 11 | `TriggerInterrupt` | host to device | `Ack` |
| 12 | `DeviceEvent` | device to host, unsolicited | — |
| 13 | `NetworkConfig` | host to device | `Ack` |
| 14 | `FactoryReset` | host to device | `Ack` |
| 15 | `AssetBegin` | host to device | `Ack` |
| 16 | `AssetChunk` | host to device | `Ack` |
| 17 | `AssetCommit` | host to device | `Ack` |
| 18 | `AssetRelease` | host to device | `Ack` |
| 19 | `PushScene` | host to device | `Ack` |

Request-only and response-only types used in the wrong direction receive
`UnsupportedMessage`. Unknown types do too. A syntactically valid envelope with another
version receives `VersionMismatch`; framing errors without a trustworthy request ID are
discarded.

Types 13 and 14 are gated by capability bit 7 (`Networking`, see below); a host must not
send either to a device that has not advertised it. `Ack` for these two types is added
to the acknowledged-type registry by the V2 task that implements device-side handling —
this task defines only the wire shape and decode/encode/validation of the requests
themselves.

Types 15-18 are gated by capability bit 5 (`AssetTransfer`, see below); a host must not
send any of them to a device that has not advertised the bit. Content addressing by
digest means there is no separate query message and no list to keep in sync: the host
offers a digest via `AssetBegin` and the device's `Ack` reports whether the bytes are
already present, so the host can skip re-sending an asset it already staged. In addition,
`AssetBegin` with `volatile = true` requires bit 9 (`VolatileAssets`); bit 5 alone does
not promise that tier, because deployed bit-5 devices accept durable transfers while
explicitly refusing volatile ones.

Type 19 is gated by capability bit 8 (`SceneRender`, see below); a host must not send it
to a device that has not advertised the bit. The device dispatches it synchronously under
the LVGL lock, building the decoded scene onto a candidate screen before loading it. `Ack`
carries the accepted `revision`, the same as `PushData` and `ApplyConfig`. A refusal
answers `Busy` if something else currently owns the panel (in practice, an OTA takeover)
and `InvalidPayload` if the scene itself could not be rendered — an unallocatable object or
an asset that could not be acquired. Either refusal leaves the previously shown scene (or
the standalone clock, or a template view) on the panel: a candidate screen is only loaded
once every node and every asset succeeds, so a refused `PushScene` never blanks the
display.

## CBOR payloads

All schema keys below are unsigned integer keys except `PushData.fields`, whose keys are
UTF-8 text sorted by deterministic CBOR key order (encoded length, then bytewise). Unknown
integer keys are skipped. Duplicate keys, missing required keys, indefinite items,
non-shortest integers, invalid UTF-8, trailing payload bytes, and wrong types are errors.
Receivers cap CBOR recursion at eight containers so unknown extension values cannot
exhaust an embedded task stack.

- `StatusRequest` and `Heartbeat`: empty map `{}` (`a0`).
- `TimeSync`: `{0: unix_seconds, 1: utc_offset_minutes}`. Seconds are signed/unsigned
  integer in `1577836800..4102444800` (2020-01-01 through 2100-01-01 UTC); offset is
  `-840..840` minutes.
- `PushData`: `{0: widget_id, 1: revision, 2: fields}`. `widget_id` is 1..32 UTF-8
  bytes; revision is `u32` and must be newer than the retained revision; fields is a map
  of 0..16 unique keys of 1..32 UTF-8 bytes to a UTF-8 string of at most 128 bytes, an
  `i64`, or a boolean. The complete payload must still fit the envelope maximum.
- `Ack`: `{0: acknowledged_type}`, optionally with `1: revision` and/or `2:
  already_present`. Revision is present for accepted `PushData`, `ApplyConfig`, and
  `PushScene` requests and absent for `TimeSync`, `ActivateScreen`, `TriggerInterrupt`,
  `NetworkConfig`, `FactoryReset`, and all four asset messages. `already_present` is a
  boolean present if and only if `acknowledged_type` is 15 (`AssetBegin`); it reports
  whether the device already holds an asset with that digest, so the host can skip
  sending `AssetChunk`/`AssetCommit` for it.
- `HeartbeatAck`: `{0: uptime_ms}` (`u64`).
- `StatusResponse`:

| Key | Field | Type |
|---:|---|---|
| 0 | protocol version | `u8` |
| 1 | firmware version | text, 1..32 bytes |
| 2 | uptime | `u64` milliseconds |
| 3 | free heap | `u32` bytes |
| 4, 5 | display width, height | `u16` |
| 6 | brightness | `u8` |
| 7 | clockwise display rotation | `0`, `90`, `180`, or `270` |
| 8 | link state | `0` standalone, `1` online |
| 9 | latest pushed revision | `u32`, zero if none |
| 10 | valid frames | `u32` |
| 11 | malformed frames | `u32` |
| 12 | CRC failures | `u32` |
| 13 | overlong frames | `u32` |
| 14 | dropped responses | `u32` |
| 15 | transport RX drops | `u32` (zero when unavailable) |
| 16 | dropped device events | `u32` |
| 17 | device-event queue high-water mark | `u32` |
| 18 | dropped UI commands | `u32` |
| 19 | UI-command queue high-water mark | `u32` |
| 20 | applied config revision | `u32`, zero if no host config is active |
| 21 | latest accepted interrupt token | `u32`, zero if none since power-on |
| 22 | maximum protocol version | `u8`, never lower than key 0 |
| 23 | capability bits | `u64` |
| 24 | tier | `0` local, `1` networked |
| 25 | WiFi state | `0` down, `1` connecting, `2` connected, `3` failed |
| 26 | WiFi RSSI | `i8` dBm |
| 27 | device IP | text, 0..15 bytes |
| 28 | OTA state | `0` idle, `1` checking, `2` downloading, `3` pending verify, `4` failed |
| 29 | last network error | text, 0..96 bytes; present only when a network error is recorded |
| 30 | last OTA error | text, 0..96 bytes; present only when an OTA error is recorded |
| 31 | asset store stats | map `{0: used_bytes, 1: free_bytes, 2: count}`, all `u32`; present only when the asset store has been formatted |

Keys 16-31 are additive. Missing keys 16-21 default to zero. Missing key 22 defaults to
the active protocol version, missing key 23 defaults to `CoreWidgets`, missing key 24
defaults to local tier, missing key 25 defaults to WiFi down, missing key 26 defaults to
`0`, missing key 27 defaults to an empty string, and missing key 28 defaults to OTA
idle. Keys 29, 30, and 31 are omitted rather than encoded empty (or, for 31, an
all-zero map) when there is nothing to report, and a reader that does not see one of
them treats the device as having none: no network error recorded, no OTA error
recorded, and no asset store, respectively. Thus the new app can identify and safely
limit an M1-M3 firmware image. Released M3 readers skip unknown numeric keys, so they
accept current firmware responses and ignore keys 22-31. Key 21 lets a restarted
single-owner app continue the firmware's strictly increasing interrupt-token sequence
without persisting transient interrupt slots. Secrets never appear here: keys 24-31
report tier, connectivity, error presence/state, and asset store capacity only, never a
PSK or token value, and an OTA failure reason carries a stage, an error name, or a
numeric HTTP status -- never the server URL or bearer token.

### M4 version and capability negotiation

The active and maximum protocol versions are both `1` in this release. No wire-version
bump is required because the handshake and the M3 rotation field are optional map
additions, while all future wire shapes remain gated off. Capability bits are:

| Bit | Name | Meaning |
|---:|---|---|
| 0 | `CoreWidgets` | M2 clock, progress-ring, row-list, screens, data, and interrupts |
| 1 | `ConfigRotation` | companion-owned 90°/270° landscape mounting |
| 2 | `DashboardLayouts` | historical reserved bit; dashboard layouts were cancelled rather than deferred |
| 3 | `ExtendedTemplates` | `AnalogClock`, `BigNumberLabel`, and `IconBadgeText` templates (kinds 4-6) |
| 4 | `HostTapActions` | historical reserved bit; host URL/application actions are not implemented |
| 5 | `AssetTransfer` | `AssetBegin`/`AssetChunk`/`AssetCommit`/`AssetRelease` (15-18), `Ack` key 2, and `StatusResponse` key 31 |
| 6 | `FirmwareUpdate` | verified firmware update transport and `StatusResponse` key 30 |
| 7 | `Networking` | `NetworkConfig` (13), `FactoryReset` (14), and `StatusResponse` keys 24-29 |
| 8 | `SceneRender` | `PushScene` (19) and its `Ack` |
| 9 | `VolatileAssets` | accepts and resolves raw or RGB565-RLE volatile image assets in PSRAM; additionally gates `AssetBegin { volatile: true }` |

Current firmware advertises bits 0, 1, 3, 5, 6, 7, 8, and 9 (`CURRENT_CAPABILITIES` is
`1003`): core widgets, config rotation, extended templates, asset transfer, firmware
update, networking, scene rendering, and volatile assets are implemented and enabled. A device that advertises bit 3 accepts template
kinds 4-6 in `ApplyConfig`; a device without the bit rejects them with
`UnsupportedTemplate` rather than rendering a substitute. A device that advertises bit 5
accepts `AssetBegin`, `AssetChunk`, `AssetCommit`, and `AssetRelease`; a host must not
send any of them to a device that has not advertised the bit. A device that advertises
bit 7 accepts `NetworkConfig`
and `FactoryReset` requests and reports the six additive networking status fields; a host must not send
either message to a device that has not advertised the bit, and a device without it
predates V2 entirely. A device that advertises bit 8 accepts `PushScene`; a host must
not send one to a device that has not advertised it. A device that advertises bit 9
accepts `AssetBegin` with `volatile = true` for the canonical full-panel image form; a
host must require both bits 5 and 9 before sending that form. A pre-handshake firmware is treated as bit 0 only. Unknown high
bits are retained in diagnostics and otherwise ignored. Before an
app persists a draft for a connected device, it compares the deterministically compiled
requirements with the advertised bits. Missing bits produce a typed validation error;
the draft, runtime state, config revision, and device state remain unchanged. The device
session repeats the check before encoding `ApplyConfig`, so direct callers also cannot
partially mutate an older device.

- `NetworkConfig`: `{1: ssid, 2: psk, 3: server_url, 4: device_id, 5: token,
  6: utc_offset_minutes, 7: tier}`. All seven keys are required; keys start at 1 (not
  0). `ssid` is 0..32 UTF-8 bytes, `psk` is 0..64, `server_url` is 0..128, `device_id`
  is 0..32, `token` is 0..128; `utc_offset_minutes` reuses the `TimeSync` bound
  (`-840..840`); `tier` is `0` (local) or `1` (networked). Unlike every other message in
  this registry, an unrecognized key inside the map is rejected rather than skipped:
  this is a closed, credential-carrying schema, not an additive one. Secrets travel
  down only — `StatusResponse` never echoes a PSK or token value back.
- `FactoryReset`: empty map `{}` (`a0`), matching `StatusRequest` and `Heartbeat`.
- `AssetBegin`: the additive key table is:

  | Key | Field | Presence and meaning |
  |---:|---|---|
  | 0 | `digest` | required 32-byte SHA-256 `bstr` of the decoded asset blob |
  | 1 | `kind` | required: `1` (`Font`), `2` (`IconFont`), or `3` (`Image`) |
  | 2 | `total_length` | required `u32` in `1..1048576`; the wire length addressed by every `AssetChunk` offset and by `AssetCommit` |
  | 3 | `volatile` | boolean; always emitted (deployed decoders require the key), tolerated as absent-means-`false` by decoders from the encoding change onward |
  | 4 | `encoding` | optional `u8`, default raw (`0`); RGB565 RLE is `1`, and unknown values are refused |
  | 5 | `decoded_length` | optional `u32`; required if and only if `encoding != 0` |

  The device replies with `Ack` carrying `already_present`. Durable transfers refuse
  every non-raw encoding. When `volatile` is true, bit 9 is also required and `kind`
  must be `Image`. The decoded form is exactly 329,740 bytes: a canonical 12-byte
  little-endian LVGL image header (`magic = 0x19`, `cf = RGB565 = 0x12`, width 448,
  height 368, stride 896, all flags/reserved bytes zero) followed by 448×368×2 RGB565
  bytes. Raw encoding omits keys 4 and 5 and sends that blob unchanged. RLE encoding
  sends the 12-byte header unchanged, followed by `(u16 count LE, u16 pixel LE)` runs;
  key 5 must then be 329,740, key 2 remains the encoded wire length, and an encoding
  that does not shrink the blob is refused in favor of the legal raw form. The SHA-256
  digest always addresses decoded bytes, so scene references do not depend on the wire
  encoding. The device holds at most two decoded PSRAM allocations: the displayed frame
  and one incoming atomic replacement. It never downgrades a volatile transfer to flash.
- `AssetChunk`: `{0: digest, 1: offset, 2: data}`. All three keys are required. `digest`
  is a 32-byte `bstr` addressing the asset opened by a prior `AssetBegin`; `offset` is a
  `u32` byte offset into the asset; `data` is a `bstr` of at most 1920 bytes. The 1920
  bound is deliberately short of the 2034-byte envelope payload cap: the CBOR map
  header, the 32-byte digest with its `bstr` header, the offset key/value, and the data
  `bstr` header cost roughly 46 bytes, and 1920 leaves margin beyond that.
- `AssetCommit`: `{0: digest}`. The single key is required; `digest` is the 32-byte
  `bstr` of the asset being finalized.
- `AssetRelease`: `{0: [digest, ...]}`. The single key is required and holds an array of
  0..32 32-byte `bstr` digests forming the complete keep-set across durable and volatile
  tiers. Every committed digest absent from the array may be reclaimed; an empty array
  therefore means “release everything”, not “release nothing”.
- `PushScene`: `{0: card_id, 1: revision, 2: scene}`. All three keys are required.
  `card_id` is 1..32 UTF-8 bytes; `revision` is a nonzero `u32`, required here for the
  same reason it is on `PushData` — a scene the host cannot pin a revision to is one it
  cannot tell apart from the scene already on the panel. `scene` is a nested map, not a
  payload of its own; its shape is below. A `PushScene` replaces whatever the named card
  was drawing.

### The scene map

Every map below has unsigned-integer keys in strictly increasing order, definite length,
and shortest-form heads. Unknown integer keys are **skipped**, so a later revision can add
a field without stranding a deployed device; a key that repeats or goes backwards is
rejected, because that is a malformed encoder rather than a newer one.

A **required** key is always emitted. An **optional** key is emitted only when its value
differs from the default listed here — the canonical emission rule, which both
implementations follow. It is not tidiness: a baked-font text node that spelled out an
unused 32-byte digest would waste 34 bytes, and 24 of those would nearly fill the
2034-byte envelope.

| Map | Shape | Required | Defaults |
|---|---|---|---|
| scene | `{0: revision (u32), 1: background (u32), 2: [node, …]}` | 0-2 | — |
| node | `{0: kind, 1: <kind-specific map>}` | 0, 1 | — |
| `Rect` (1) | `{0: x, 1: y, 2: w, 3: h, 4: radius, 5: fill, 6: opacity, 7: <clip>}` | 0-3 | radius 0, fill 0, **opacity 255**, clip absent |
| `Arc` (2) | `{0: cx, 1: cy, 2: r, 3: start_deg, 4: end_deg, 5: width, 6: color, 7: rounded, 8: end_binding, 9: opacity, 10: running_color}` | 0-5 | color 0, rounded false, end_binding `""`, **opacity 255**, running_color absent |
| `Line` (3) | `{0: [x, …], 1: [y, …], 2: width, 3: color, 4: pivot_x, 5: pivot_y, 6: length, 7: angle_binding}` | fixed: 0-2; bound: 2, 4-7 | color 0 |
| `Text` (4) | `{0: x, 1: baseline_y, 2: w, 3: align, 4: <font>, 5: color, 6: <value>, 7: ellipsize, 8: running_color}` | 0, 1, 2, 4, 6 | **align 1 (`Left`)**, color 0, ellipsize false, running_color absent |
| `Image` (5) | `{0: x, 1: y, 2: w, 3: h, 4: digest, 5: recolor, 6: color}` | 0-4 | recolor false, color 0 |
| `Glyph` (6) | `{0: x, 1: baseline_y, 2: size, 3: digest, 4: name, 5: color}` | 0-4 | color 0 |
| `Scale` (7) | `{0: x, 1: y, 2: box, 3: total_tick_count, 4: major_tick_every, 5: major_tick_color}` | 0-4 | major_tick_color 0 |
| `Label` (8) | `{0: x, 1: y, 2: <font>, 3: <value>, 4: ink, 5: fill, 6: fill_opacity, 7: radius, 8: pad_hor, 9: pad_ver, 10: letter_space, 11: hide_when_empty, 12: horizontal_anchor}` | 0-3 | ink 0, fill 0, fill_opacity 0 (`LV_OPA_TRANSP`), radius/padding/letter_space 0, hide_when_empty false, horizontal_anchor 0 (`Left`) |
| `RotRect` (9) | `{0: x, 1: y, 2: w, 3: h, 4: radius, 5: fill, 6: pivot_x, 7: pivot_y, 8: rotation, 9: rotation_binding, 10: <clip>}` | 0-3 | radius/fill/pivot/rotation 0, rotation_binding `""`, clip absent |
| font | `{0: kind, 1: baked_tier, 2: digest, 3: pixel_size}` | 0, plus 2 when kind is 2 (`Asset`) | — |
| value | `{0: kind, 1: literal, 2: binding}` | 0 | literal `""`, binding `""` |
| clip | `{0: x, 1: y, 2: w, 3: h}` | 0-3 | — |

Two defaults are not the zero value and both matter: an omitted `opacity` on either a
`Rect` or an `Arc` is opaque (0 would draw nothing), and an omitted `align` is `Left`,
which is **1**, so a zero-initialised align is the invalid value the device rejects.

A font's digest is required for kind 2 (`Asset`) specifically rather than for the map as
a whole: an asset font with an all-zero digest passes every other check and then fails at
draw time when the lookup misses, and the rule here is that a scene is refused whole
rather than left half-drawn.

On `Arc` and `Text`, an optional `running_color` replaces `color` while the active timer
snapshot says `running = true`. It is reselected on every binding refresh, so a
start/pause transition repaints without a scene re-push. Omission means there is no
running variant and preserves every previously encoded scene's colour.

Bounds, all rejected rather than clipped, and identical in both implementations: at most
**24** nodes; text literals at most **128** bytes; bindings and `end_binding` at most
**48** bytes; glyph names at most **32** bytes; a fixed line's two coordinate arrays must
be the same length, between **2** and **8** points; `total_tick_count` in `2..=361` and
`major_tick_every` in `1..=total_tick_count`; asset-font `pixel_size` in `8..=200`;
digests exactly 32 bytes. Every fixed-box node's geometry must lie fully inside the
448×368 canvas. A `Label` is content-sized by LVGL, so the model bounds its anchor and
style extents but deliberately does not reimplement font measurement to predict its
right/bottom edge; a Left/Center `x` is in `0..448`, a Right `x` is in `1..=448`, `y` is
in `0..368`, and radius/padding/tracking are non-negative and canvas-bounded. A
`Rect.clip` and `RotRect.clip`, when present, are absolute boxes that must themselves lie
fully on-canvas.
`RotRect`'s untransformed box must be on-canvas; its local pivot may be outside that box
but is bounded independently to `pivot_x` in `0..=448` and `pivot_y` in `0..=368`, and
its rotation is in `-3600..=3600` tenths of a degree. Those axis-specific bounds admit
the analog clock's external tick pivot while keeping every corner-to-pivot delta at
canvas scale before the rotation matrix mixes axes.
A bound `Line` carries no point arrays. Its pivot is independently bounded to
`pivot_x` in `0..=448` and `pivot_y` in `0..=368`, and its non-negative length must fit
from that pivot to every canvas edge so every future angle stays on-canvas. A payload
carrying any explicit point array together with bound geometry is rejected: the device
never chooses between two sources for the same endpoint.
The decoder distinguishes exactly one of these from the rest — more than 24 nodes is a
capacity answer a host can act on by splitting the scene, and reaches the message layer
as `TooLarge`; every other scene failure arrives as `InvalidValue`, because the scene
model has no CBOR-specific result code and none was added.

`Arc` angles are absolute canvas angles in LVGL's convention: 0° is 3 o'clock and angles
increase **clockwise**. A full turn is spelled as a nonzero exact multiple of 360 — a ring
starting at twelve o'clock is `start_deg = 270, end_deg = 630` — and **not** as
`start_deg == end_deg`, which is a degenerate empty arc that draws nothing.
`Arc.opacity` applies to the indicator before LVGL's anti-aliasing coverage mask, so edge
pixels preserve the same opacity-times-mask blend as a template `lv_arc`.

`Rect.clip` and `RotRect.clip` clip only their own node. Both use the shared `clip` map;
`RotRect` assigns it key 10, the next key after its existing 0-9 layout. The device realizes
either clip by parenting the node under a styleless object whose box is the absolute clip
rectangle. LVGL clips children to their parent, while a scene's display list is otherwise
flat with every node parented directly to the screen, so a C template that relies on a
container to clip overflowing geometry must express that clip on the scene node. These are
the two node kinds among the six scene templates that require it; the other seven kinds do
not speculatively carry the field. This deliberately uses LVGL's normal child-clipping path
rather than reproducing its mask arithmetic in the host.

`Text.baseline_y` and `Glyph.baseline_y` are baselines, not box tops.

`Label` is an LVGL label with its own background and content-sized box. The device, not
the host, computes `text_width + 2 * pad_hor`, including the selected font's glyph
advances, kern pairs and `letter_space`. `fill_opacity = 0` is the transparent eyebrow
form. When `hide_when_empty` is true, an empty evaluated value hides the whole object
rather than leaving a collapsed coloured pill. Only the horizontal box anchor is carried:
key 12 is `0` (`Left`), `1` (`Center`), or `2` (`Right`). Accordingly, `x` is the left
edge, horizontal centre, or right edge of the finished box; `y` is always its top edge.
Omitting key 12 means `Left`, preserving the original scene-v1 label semantics. Unknown
anchor values are rejected. There is deliberately no vertical-anchor key: the host knows
the box height from the baked font's line height and its own `pad_ver`.

`RotRect` is an LVGL object transformed about `(pivot_x, pivot_y)`; it is not a line and
therefore follows LVGL's object-transform anti-aliasing path. `rotation` is already in
tenths of a degree. An empty `rotation_binding` uses that fixed value; the closed dynamic
set is `time:hour`, `time:minute`, and `time:second`, evaluated locally so clock hands
continue ticking without a scene re-push.

A bound `Line` remains an `lv_line`, preserving the line renderer's anti-aliased edges.
Its closed `angle_binding` set is `time:angle:hour` and `time:angle:minute`. On each
refresh the device derives the local angle from `unix_seconds + utc_offset_minutes * 60`
as `hour = (h % 12) * 30 + m / 2` or `minute = m * 6`; the hour formula's integer
division deliberately advances the hour hand once every two minutes. It computes the
endpoint with LVGL's own fixed-point trig table using
`(length * trigo_cos(270 + angle)) >> LV_TRIGO_SHIFT` (and the corresponding sine).
The fixed form omits keys 4-7 and behaves exactly as before.

A `binding` (and an `Arc`'s `end_binding`) is drawn from a closed set the device
evaluates locally, which is what keeps a bound clock ticking with the link down. The
grammar is exactly: `date`; `timer.pct`; `timer.permille`; `timer.status`; `time:<fmt>`;
`timer.remaining:<fmt>`; `timer.elapsed:<fmt>`; `timer.total:<fmt>`; and `field.<name>`
with a non-empty name. A `time:` format is a non-empty string of `H h M m S s :`;
every `timer.*:<fmt>` format is a non-empty string of `M m S s :` and rejects hour
tokens. Both are whitelists, never printf format strings. A scene
naming any other binding is refused whole at decode.
`date` applies the UTC offset, breaks down local time, and delegates its text to
`timefmt_date()` (`Mon, Aug 3`, with a Monday-based weekday index and unpadded day).
`timer.pct` is the timer's **remaining** percentage (100 before it starts and 0 when it
finishes); `timer.permille` is the same remaining ratio at 0..1000 resolution for arc
geometry. `timer.elapsed` is total minus the displayed remaining time, `timer.total` is
the bounded duration, and `timer.status` is `Done`, `Running`, `Ready`, or `Paused` (or
`--` when no timer snapshot is active). In a `timer.*` format argument, `mm` is total
minutes; in a `time:` argument, `mm` is the wall clock's minute component.

- `Error`: `{0: code, 1: diagnostic}`. Diagnostic text is at most 96 UTF-8 bytes and is
  for humans, not program logic.

Codes 1-9 retain their M1 values. Duplicate identifiers, invalid enum combinations,

device is currently reachable over for its current tier (for example, a networked
device rejecting a message that only makes sense over USB, or vice versa); the specific
transport/tier rules are defined by the V2 task that implements them, not by this wire
contract.

## M2 configuration and interaction contract

### Capacity and enum registry

- A configuration contains 1..8 widget instances and 1..8 ordered screens.
- Widget IDs and screen IDs are distinct namespaces. Each is 1..32 UTF-8 bytes and
  unique within its namespace. A screen references one configured widget; configured
  widgets may be interrupt-only and therefore need not have a carousel screen.
- Interrupt reasons are 0..96 UTF-8 bytes. Interrupt tokens are nonzero `u32` values.
- Event sequences are nonzero `u64` values.

**Clarifying note (size class, M4 card model, wire unchanged):** from config schema v3
onward, the host compiles every card to a widget with `size_class`
pinned to `Full`; it never emits `Standard` or `Tile`. Those two values remain in the
wire registry below **for decode compatibility only** — an M3-era or hand-crafted
`ApplyConfig` may still name them, and the firmware must continue to accept `Standard`
and reject an unsupported/malformed class exactly as it does today. This is a
documentation note about which values the current host emits; the registry, its
numbering, and `UnsupportedSizeClass` behavior are unchanged.

| template | 1 | `DigitalClock` | supports `full`, `standard` |
| template | 2 | `ProgressRing` | supports `full`, `standard` |
| template | 3 | `RowList` | supports `full`, `standard` |
| template | 4 | `AnalogClock` | supports `full`, `standard`; requires `ExtendedTemplates` |
| template | 5 | `BigNumberLabel` | supports `full`, `standard`; requires `ExtendedTemplates` |
| template | 6 | `IconBadgeText` | supports `full`, `standard`; requires `ExtendedTemplates` |
| size class | 1 | `Full` | clean full canvas |
| size class | 2 | `Standard` | legacy M2 class; clean full canvas in M3; reserved decode-only, never emitted from schema v3 onward |
| size class | 3 | `Tile` | reserved; rejected in M2; reserved decode-only, never emitted from schema v3 onward |

| interrupt policy | 1 | `Enabled` | may occupy the active/pending slots |

Unknown template numbers receive `UnsupportedTemplate`; known template/size
combinations not implemented in M2 receive `UnsupportedSizeClass`. Other unknown enum
numbers are invalid payloads.

### `ApplyConfig`

Payload: `{0: revision, 1: widgets, 2: screens, 3: rotation}`.

- `revision` is a nonzero `u32` in a configuration-specific revision domain.
- `widgets` is an array of widget maps
  `{0: widget_id, 1: template, 2: size_class, 3: tap_action, 4: interrupt_policy}`.
- `screens` is the carousel-order array of screen maps
  `{0: screen_id, 1: widget_id}`.
- `rotation` is `90` for landscape with the USB cable below or `270` for the flipped
  landscape mounting. It is an additive M3 field; a missing value decodes as `90` for
  compatibility with earlier v1 fixtures and hosts. Portrait values are rejected.

The device validates the complete candidate before changing live state. A higher
revision atomically replaces the prior config. The same revision with a semantically
identical config is an idempotent replay and is acknowledged; the same revision with
different content, or a lower revision, receives `StaleRevision`. A rejected config
does not change the live model, revision, active carousel screen, or interrupt state.
An accepted replacement preserves the active screen when that screen ID still exists,
otherwise selects the first screen; it clears active and pending interrupts without
emitting dismissal events. The `Ack` echoes type 9 and the accepted config revision.

`StatusResponse` key 20 is the connect-time config handshake. A reconnecting host may
skip an already-applied revision or replay it idempotently. Configuration revision and
`PushData` revision are independent domains.

The deterministic maximum-capacity fixture uses eight widgets, eight screens, and
32-byte IDs throughout. Its encoded `ApplyConfig` payload is **935 bytes**, leaving
1,099 bytes below the 2,034-byte payload limit. Both Rust and C assert that measured
size and re-encode the fixture byte-for-byte.

### `ActivateScreen`

Payload: `{0: screen_id}`. The selected screen must exist in the current config. The
operation is idempotent and does not change carousel order. Unknown IDs receive
`UnknownScreen`; success returns `Ack` for type 10 without a revision. While a priority
interrupt is active, activation changes the saved underlying carousel screen; the
interrupt remains visible and dismissal restores the newly selected screen.

### `TriggerInterrupt`

Payload: `{0: widget_id, 1: token, 2: reason}`. The widget must exist and have interrupt
policy `Enabled`. Tokens are strictly increasing among accepted nonduplicate triggers.
A token already present in the active or pending slot is an idempotent replay and is
acknowledged only when widget and reason are also identical. Reusing that token with
different content, or sending an older token, receives `StaleRevision`.

The first accepted trigger becomes active and saves the exact carousel screen. While
one interrupt is active, one newer trigger may occupy a FIFO pending slot. A further
new token receives `Busy` and is not consumed, so it may be retried after space opens.
Dismissal emits one event for the active token, then promotes the pending slot or
restores the saved carousel screen. Success returns `Ack` for type 11 without a
revision. M2 has no automatic interrupt timeout: a tap dismisses the active interrupt,
and host loss temporarily replaces all host content with the standalone clock without
discarding the interrupt slots.

### `DeviceEvent`

Payload:
`{0: sequence, 1: event_kind, 2: widget_id, 3: screen_id, 4: action}` or the same map
with `{5: interrupt_token}`. Keys 0-4 are always required. Key 5 is required only for
`InterruptDismissed` and forbidden for other event kinds. Widget and screen IDs name
the source widget and the underlying/current carousel screen; for a dismissal,
`screen_id` is the saved carousel screen that will be restored after pending-interrupt
promotion completes.

Delivery is at-most-once: events are not acknowledged or retransmitted. The device
assigns sequence numbers when enqueueing, increments them monotonically from one, and
drops the newest event if the bounded event queue is full. A gap lets the host detect
loss but not recover the event. Duplicate or out-of-order events are ignored by the
host. The next authoritative `PushData` reconciles any optimistic local tap feedback.

### Local gesture and animation semantics

LVGL supplies points in the current logical 448x368 landscape coordinate system for
both 90- and 270-degree display rotations. A tap lasts at most 500 ms and moves no more
than 18 pixels on either axis. A horizontal swipe lasts at most 750 ms, moves at least
`max(56, logical_width / 6)` pixels on the primary axis (74 pixels at 448 wide), and its
horizontal displacement is at least 1.5 times its vertical displacement. A left swipe
selects next; a right swipe selects previous. Other releases emit no event.

Orientation has no local touch gesture. The companion owns the two landscape mounting
choices through `ApplyConfig`, and the device keeps that orientation when it falls back
to the standalone clock until a later config or reboot changes it.

Progress-ring `remaining_seconds` is an authoritative snapshot. While `running` is
true, firmware advances the ring from that snapshot on a 250 ms LVGL timer using a
monotonic tick; no per-frame host push is required. Start/pause/reset taps apply bounded
optimistic visual feedback immediately. The next complete `PushData` snapshot always
replaces that local feedback, including after an event was dropped under pressure.

## M2 template field registry

`PushData` remains `{0: widget_id, 1: revision, 2: fields}`. Its revision is global
across all widgets for the current powered device, not per widget: each accepted push
must be numerically greater than `StatusResponse.latest_revision` and the last accepted
push. A host seeds its next revision from status key 9 after every connect. Rejected
pushes do not consume a revision. Revision zero is invalid and wrapping is not supported
within one powered session.

Field names below are the wire keys directly; configuration contains no binding/rename
table. Unknown names remain schema-valid for forward compatibility and are ignored by
the model layer. Duplicate names remain a canonical-CBOR error. `stale` and

visual precedence over `stale=true`.

changing the prior field state. To enter an error presentation while preserving
last-good values, the host sends a complete valid snapshot containing those values plus
the bounded `error` field (and `stale` when applicable).

## Liveness and state

Boot state is standalone. Every valid request, including heartbeat, changes state to
online and refreshes a 10,000 ms deadline. Invalid traffic never refreshes it. Expiry
returns to standalone, restores the clock connection hint, and leaves the last valid
time and pushed sample intact. The device stores UTC; rendering adds the fixed signed
offset supplied by the latest valid `TimeSync`. The companion refreshes the offset when
it reconnects (and later across DST changes).
