# Deskmate v1 provider contract

All file and network I/O stays in the Rust companion runtime. The webview and firmware
receive only bounded typed fields. Provider jobs use one fixed-capacity worker queue;
one widget can have at most one job in flight. A config generation invalidates late
results, manual refreshes coalesce, and interval deadlines advance from the actual job
start so a sleep/wake event cannot enqueue a backlog.

Every provider keeps its last successful value and timestamp in memory. A failed
refresh reports one of the stable categories (`io`, `timeout`, `redirect`,
`http-status`, `oversized`, `encoding`, `malformed`, `unsafe-content`, or
`invalid-configuration`) while continuing to project the last-good fields with their
age. Provider payloads are transient and are never persisted in config.

## Shared HTTP boundary

- HTTP and HTTPS only, with a required host and no URL credentials.
- 10-second global request timeout.
- At most three redirects; exceeding the limit is an error.
- At most 1,048,576 response bytes, decoded as strict UTF-8.
- Transport errors never echo a request URL, query, location, or credential-like value.

The built-in weather adapter uses Open-Meteo's public geocoding and forecast endpoints.
It sends the configured location, resolves one coordinate pair, and requests only the
current temperature, apparent temperature, WMO weather code, and day/night flag. Unit
selection is explicit (`metric`/Celsius or `imperial`/Fahrenheit), no service key is
stored, and refresh intervals are clamped and validated to at least ten minutes.

## JSON, RSS, and Atom

JSON feeds are parsed only after the shared byte bound. A mapping path is `$` followed
by at most 16 direct object-name or array-index segments; array indexes are `0..1023`.
Mappings may resolve only to null, boolean, number, or string values. Objects, arrays,
wildcards, recursive descent, filters, and user code are rejected. Text sent to the
device is capped at the protocol's 128-byte field limit.

RSS 2.0 and Atom entries expose only a plain title, optional HTTP(S) link, and optional
published/updated text. Parsing is limited to 100,000 XML events, 32 levels, 4,096
bytes of accumulated item text, and five output items. DTDs, processing instructions,
active elements, event handlers, and active URL schemes are rejected. Inert markup is
stripped and whitespace collapsed before a value can reach app state or firmware.

## ICS recurrence boundary

Calendar expansion is deterministic inside the configured occurrence horizon and the
existing 100,000-day scan ceiling. v1 supports:

- `FREQ=DAILY|WEEKLY|MONTHLY|YEARLY`, `INTERVAL`, `COUNT` or `UNTIL`, and `WKST`;
- `BYDAY`, including positive/negative ordinal weekdays for monthly/yearly rules;
- positive/negative `BYMONTHDAY`, `BYMONTH`, and positive/negative `BYSETPOS`;
- `RDATE`, `EXDATE`, IANA `TZID` values, UTC/floating/all-day values, and DST changes;
- single-instance `RECURRENCE-ID` moves and cancellations, selected by highest
  `SEQUENCE` with stable source-order tie breaking.

Sub-daily frequencies, `BYHOUR`/`BYMINUTE`/`BYSECOND`, `BYYEARDAY`, `BYWEEKNO`,
period-valued `RDATE`, and `RANGE=THISANDFUTURE` remain intentionally unsupported.
Their events are skipped and counted rather than approximated.
